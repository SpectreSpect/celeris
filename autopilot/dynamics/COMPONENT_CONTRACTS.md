# Контракты компонентов траектории

Полные нормативные обязательства записаны в комментариях соответствующих
заголовков. Концепты и интерфейсы проверяют форму операций; конечные наборы
тестов проверяют выбранные истории и не являются доказательством всех законов.

## Границы полиморфизма

| Компонент | Форма | Заголовок |
|---|---|---|
| Кэш вычисленных значений | `trajectory_cache<Cache, Y>` | `trajectory_cache_concept.h` |
| Источник заданных значений | `prescribed_values_source<Source, Y>` | `prescribed_values_concept.h` |
| Вычислитель | `TrajectoryEvaluatorInterface<Y>` | `trajectory_evaluator_interface.h` |

Кэш и источник выбираются статически, вычислитель — динамически при фиксированном
`Y`. Для этой композиции `Y` — копируемое значение. Не требуются его конструктор
по умолчанию и `operator==`; тесты могут принимать собственное сравнение.
Копии не должны предоставлять обходной mutable-доступ к сохранённым значениям.
Сам `TrajectoryInterface<Y>` остаётся более широким, включая некопируемые `Y`.
Требуется копирующее конструирование Y, но не копирующее присваивание.

## Кэш

Операции: `find(t) -> optional<Y>`, `store(t, y)`, `invalidate(region)`.
Вытеснение и отсутствие хранения допустимы. Попадание должно соответствовать
последней записи ключа; успешно инвалидированные записи возвращать нельзя.
После исключения допустима потеря записей, но не повреждение оставшихся значений.

Обязателен приём `const InvalidationRegionInterface&`. Дополнительные статические
перегрузки разрешены. Кэш не знает причин инвалидирования и версии траектории.

## Источник

Операции: `find(t) -> optional<Y>`, `set(t,y)`, `erase(t)`, const-обход,
`lower_bound(t)` и `upper_bound(t)`. Диапазон двунаправленный, общий, строго
упорядоченный по уникальным ключам. Границы возвращают его const-итераторы.
Изменение сохраняет все остальные записи. При исключении логическое D прежнее.
Самовольного вытеснения нет. Итераторы не переносятся через изменения.

Источник может быть некопируемым и требовать аргументы конструктора. В композиции
исключительное право его изменения принадлежит адаптеру; наружу выдаётся только
чтение и управляемые операции обновления.

`PrescribedValuesView<Y, Source>` — заимствующий динамический мост, а не снимок
данных. Он возвращает копии через единый `PrescribedValuesViewInterface<Y>`.
`at_or_before(t)` позволяет получить последнюю опору с временем <=t. Полный граф
доступен через `lower_bound(Timestamp::min())` и последовательные `upper_bound`.
Представление не переживает уничтожение источника. Оно отражает новое D после
завершённого обновления того же объекта источника; на время вычисления, проверки
совместимости и применения предиката D фиксировано. Это live-view без сохранения
старых версий. Итераторы самого источника через изменяющий вызов не сохраняются.

## Вычислитель

NVI-операции: `compatible(D)`, `evaluate(t, context)`,
`invalidation_region(D, change)`. Пользователь реализации переопределяет закрытые
виртуальные методы `*_impl`. По умолчанию совместим любой источник; дополнительные
предусловия должны быть явно выражены в `compatible`, то есть в отношении Q(D,E).

При фиксированных совместимых E,D определяется f на всём Timestamp. Заданные
значения имеют приоритет: f(t)=D(t) для заданных t. Остальные точки вычисляются
через E. Результат не зависит от порядка запросов и кэша. Политика сетки/опор,
завершение всей рекурсии и сохранность состояния вложенных вызовов — обязанности E.
Forward-only вычислитель обязан явно определить значения до начала интегрирования.

`TrajectoryEvaluationContext<Y>` даёт только чтение D и `resolve(t)` той же
траектории. Он не раскрывает типы хранения и не позволяет менять данные. Контекст
заимствуется на время вызова. Многопоточность и внешние изменения во время запросов
в этой версии не поддерживаются.

## Инвалидирование и ранги

Область — стабильный предикат p(t), для которого `!p(t)` гарантирует равенство
f(E,D,t) и f(E,D',t), где D'=change(D). Консервативная область, включая всё время,
допустима. Учитывается и прямое, и транзитивное влияние. Null-указатель запрещён,
пустая область представляется настоящим объектом с ответом false для всех t.

`IntervalInvalidationRegionInterface` — необязательное усиление: предикат точно
равен объединению интервалов. `TimeInterval` имеет семантику [lower,upper),
отсутствующая граница не ограничивает время. Пересечения, пустые интервалы,
несортированный список и Timestamp::min/max поддерживаются.

`invalidation_intervals` выбирает статическую возможность через `if constexpr`
либо динамическую через `dynamic_cast` (нужен RTTI). Для неизвестного предиката
точный выбор ключей обычно требует полного просмотра; описание интервалов
сохраняет возможность поиска границ и удаления диапазонов.

`RankedTrajectoryEvaluatorInterface<Y>` необязателен. При каждом `resolve` к
незаданной точке ранг строго убывает, включая запросы, обслуженные кэшем. Ранги
стабильны для фиксированных E,D,t. Это диагностируемая гарантия структуры
зависимостей, а не проверка завершения произвольного локального кода.

## Протокол адаптера

`TrajectoryAdapter<Y, Cache, Source>` принимает во владение кэш, источник и
вычислитель через `std::unique_ptr`. Конструктор проверяет совместимость E и D
и инвалидирует начальное содержимое кэша. `source_view()` даёт доступ для чтения
к текущему D на время жизни адаптера.

`operator()(t)` ищет заданное значение, затем обращается к кэшу. При промахе
адаптер вызывает `E.evaluate` и записывает вычисленный результат. Вложенные
`resolve` используют ту же версию E и D. Для ранжированного вычислителя проверка
убывания ранга предшествует чтению из кэша. Для обычного вычислителя проверяется
повторный вход в активное вычисление той же точки. При исключении из вычислителя
его завершённые дочерние результаты могут сохраняться в кэше.

Операция `change` принимает `SetPrescribedValue<Y>` или `ErasePrescribedValue`.

1. Проверить совместимость D' с E через временное представление с одной правкой.
   Представление читает данные из текущего D и учитывает добавление или удаление
   одной точки при поиске. Создавать копию источника для этого не требуется.
2. Получить регион по прежнему D и описанию изменения.
3. Инвалидировать кэш, пока прежний D и заимствования предиката действительны.
4. Применить изменение источника с его строгой гарантией исключений.

Ошибка до шага 4 сохраняет прежний D; ошибка шага 4 тоже сохраняет его. Кэш
может стать менее полным, но его оставшиеся записи корректны.
`replace_evaluator` проверяет совместимость нового E с D, целиком очищает кэш
и затем заменяет E. Обновление и замена выполняются между запросами.

## Проверки

Из корня репозитория:

```sh
cmake -S autopilot/dynamics/tests -B build/dynamics-contract-tests
cmake --build build/dynamics-contract-tests
ctest --test-dir build/dynamics-contract-tests --output-on-failure
```

Наборы `trajectory_cache_contract_tests.h`, `prescribed_values_contract_tests.h`
и `trajectory_evaluator_contract_tests.h` переиспользуются с фабриками моделей.
Ограничения fixture-ов документированы отдельно от контрактов компонентов.

В тестах используются несколько реализаций хранения, отсутствие кэша, вытеснение,
необязательные ранги, экстремальные времена, ошибки копирования и предикатов,
обновления и замена E при прогретом кэше. Намеренно неверные модели проверяют,
что набор действительно обнаруживает нарушения. `EvaluatorContractFixture`
направляет запросы и обновления в `TrajectoryAdapter` и позволяет тестам читать
содержимое тестового кэша и обращаться к установленному вычислителю.
